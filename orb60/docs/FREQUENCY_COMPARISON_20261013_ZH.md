# 2026-10-13：2PPC／4PPC与100／125MHz最终对照

本轮选择**4PPC／125MHz**作为最快的电脑验证版本，同时保留4PPC／100MHz。两者均满足完整路由硬门槛，四组DDR模型的最大整帧耗时均低于14ms。PS、ELF/XSA、代表性视频P99和实体板持续FPS仍未验收。

同一xc7z015clg485-2和默认实现流程。125MHz图像核和描述子均重新按8ns生成，不复用10ns IP，不修改Pblock、时序例外或物理优化策略。

新版本TNS／THS均为0，setup／hold失败端点均为0，严格DRC、路由及约束覆盖通过。125MHz均低于争取的+0.2ns余量，但通过非负硬门槛。

4PPC／125MHz最差路径为锦标赛tree_1 BRAM输出到tree BRAM写数据：7级逻辑、7.467ns，逻辑3.267ns、布线4.200ns、98负载。2PPC／125MHz也是锦标赛BRAM反馈，6级逻辑、7.480ns。100MHz的最差路径为BRAM FIFO复位分发。FAST原16级链已拆成流水与平衡归约，其最差路径不再是125MHz完整顶层第一名。

4PPC提频比100MHz增加204LUT、3143FF、32Slice和23控制集，BRAM／DSP不变。这是频率重建产生的实际路由结果，不是旧周期缩放。

## 相同DDR字节/s与延迟ns的整帧RTL结果

HP服务上限每端口800MB/s；聚合800／1600MB/s。125MHz用10ns参照服务时隙量化到8ns边沿，未使用“每125MHz拍一个64bit传输”的1GB/s模型。读资格延迟和B响应仍为相同ns，向新时钟边沿取整的误差不足8ns。原100MHz调度和PRNG序列保留。

## 选择、当前热点与边界

4PPC125在本组匹配模型中均更快，完整路由通过，因此作为最快候选保留。4PPC100保留独立配对bit和源码，作为较低时钟版本。新2PPC125通过完整电脑门禁，保留源码／资源／周期对照；本轮不额外生成其bit。

4PPC125只剩113个Slice，不能从23%剩余LUT、61%剩余FF直接推断还能复制数据通路。下一步继续在锦标赛反馈、局部复位／CE、精确raw加载时方向矩融合、紧凑控制与打包上改善结构；BRIEF两比较／拍与Resize DDA仍是尚未实施的候选，不宣称已完成。当前候选FIFO峰值5/64未满，未触发双候选消费条件。

方向矩与CORDIC位宽、patch32及实际8读请求预取已通过完整精确门禁。它们将旧高延迟前端/后端瓶颈转移到了DDR、图像搬运和后几层描述子尾部。busy包含等待，不能仅凭busy排行增加计算并行度。压力帧仍有8.46MB流量，聚合800MB/s下至少10.58ms，数据搬运下限不会随PL提频同比减少。
